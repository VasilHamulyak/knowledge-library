# Few-Shot Prompting Techniques

## Що таке Few-Shot Prompting?

Few-Shot Prompting — це техніка Prompt Engineering, у якій моделі надається декілька прикладів правильного виконання задачі перед тим, як вона повинна виконати нове завдання.

Модель навчається на шаблоні прикладів без додаткового тренування.

---

## Основна ідея

Замість:

Task Only

(Zero-Shot)

використовується:

Examples + Task

(Few-Shot)

---

## Приклад

### Prompt

Текст: "I love this product."
Відповідь: Positive

Текст: "This service is terrible."
Відповідь: Negative

Текст: "The delivery was late."

Відповідь:

### Результат

Negative

---

## Як працює

1. Надаються приклади.
2. Модель визначає шаблон.
3. Узагальнює правила.
4. Використовує їх для нової задачі.

---

## Основні Few-Shot Techniques

### 1. Example-Based Prompting

Найпоширеніший підхід.

Приклад:

Input → Output

Input → Output

Input → ?

---

### 2. Pattern Completion

Модель продовжує заданий шаблон.

Приклад:

Question → Answer

Question → Answer

Question → ?

---

### 3. Demonstration Prompting

Показ правильного процесу вирішення.

Приклад:

Задача → Кроки → Відповідь

---

### 4. Chain-of-Thought Few-Shot

Приклади містять покрокові міркування.

Приклад:

Question

Reasoning

Answer

---

### 5. Self-Consistency Few-Shot

Генерується декілька варіантів міркувань.

Потім вибирається найчастіша відповідь.

---

### 6. Least-to-Most Prompting

Приклад показує розбиття складної задачі на простіші кроки.

---

### 7. Retrieval-Augmented Few-Shot

Приклади підбираються динамічно з бази знань або векторного сховища.

---

## Best Practices

### Використовуйте якісні приклади

Приклади повинні бути:
- точними;
- зрозумілими;
- релевантними.

### Показуйте різноманітність

Покривайте:
- типові кейси;
- крайні випадки;
- винятки.

### Зберігайте однаковий формат

Одна структура для всіх прикладів.

### Не перевантажуйте prompt

Занадто багато прикладів збільшують:
- вартість;
- затримку;
- ризик плутанини.

---

## Переваги

- Вища точність.
- Кращий контроль результату.
- Менше неоднозначності.
- Добре працює зі спеціалізованими задачами.

---

## Недоліки

- Більші prompts.
- Вищі витрати токенів.
- Потрібно підбирати якісні приклади.
- Складніше підтримувати.

---

## Zero-Shot vs Few-Shot

### Zero-Shot

- Без прикладів.
- Простий prompt.
- Швидкий запуск.

### Few-Shot

- Є приклади.
- Вища точність.
- Кращий контроль.
- Більше токенів.

## Головна думка

Few-Shot Prompting дозволяє моделі вчитися на невеликій кількості прикладів без додаткового тренування, що значно підвищує якість та передбачуваність результатів.
